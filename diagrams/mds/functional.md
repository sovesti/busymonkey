# Busy Monkey — функциональные требования

**Версия:** 1.1 · **Дата:** 10.10.2026 · **Статус:** проект для согласования командой.

ФТ описывают **возможности целевого продукта**, а не уже реализованные функции. Этапы соотносятся с `roadmap.uml`: этап 2 — базовый MVP на Windows 11 x64; этапы 3–5 — функциональность после MVP. Поддержку Windows 10, Linux и macOS проверяют на этапе 5; если команда выбирает мультиплатформенный MVP, нужно изменить и roadmap, и NFR-07.

## Функциональные требования

| ID | Этап roadmap | Требование и критерий приёмки | Состояние прототипа* |
| --- | --- | --- | --- |
| FR-01 | 2 / MVP | Пользователь задаёт интервал 50–60000 мс, величину перемещения курсора 1–100 пикселей и длительность 1–120 минут. Недопустимые значения отклоняются с объяснением до запуска. Диапазоны предварительные. | Нет UI настройки; в демонстрационном сценарии фиксированный интервал 20 мс. |
| FR-02 | 2 / MVP | Пользователь запускает базовый сценарий кнопкой либо настраиваемой горячей клавишей; используются выбранные параметры. Повторный запуск не создаёт второй исполнитель. | Есть запуск по глобальному пробелу, без выбора параметров. |
| FR-03 | 2 / MVP; расширение 4 | Пользователь останавливает сценарий кнопкой или горячей клавишей. После завершения остановки новые события не создаются. На этапе 4 добавляется отдельная экстренная горячая остановка. | Есть отмена по пробелу; кнопки остановки нет. |
| FR-04 | 2 / MVP | В MVP интерфейс показывает «Остановлен», «Работает», «Ошибка», оставшееся время и понятное сообщение об ошибке. При реализации FR-14 добавляется состояние «Пауза». Статус соответствует состоянию исполнителя. | Есть текстовая инструкция и вывод ошибки, но нет индикатора и таймера. |
| FR-05 | 2 / MVP | По окончании заданной длительности сценарий завершается без действия пользователя. Показывается причина остановки «Таймер». | Нет. |
| FR-06 | 2 / MVP | Параметры сценария сохраняются локально и восстанавливаются после перезапуска. Повреждённая конфигурация не вызывает падения: применяются значения по умолчанию и сообщение пользователю. | Нет. |
| FR-07 | 2 / MVP | Локальный базовый сценарий запускается, выполняется и останавливается без интернета, сервера и авторизации. Приёмка: запуск с отключённой сетью. | В текущем интерфейсе вход на сервер обязателен. |
| FR-08 | 4 | При обнаружении реального физического ввода пользователя сценарий **приостанавливается**, а не завершается; собственные синтетические события не вызывают ложного срабатывания. Возобновление происходит только по выбранному режиму. Приёмка: 100 физических событий вызывают паузу; 30 мин работы без ложной паузы. | Не реализовано по имеющемуся описанию. |
| FR-09 | 3 | Пользователь создаёт, выбирает, переименовывает и удаляет именованные профили параметров. Изменения сохраняются; удаление требует подтверждения. Перенос файлов описан в FR-16. | Не реализовано по имеющемуся описанию. |
| FR-10 | Доп. итерация | Пользователь видит локальную историю сеансов: время начала, длительность, профиль и причину остановки. Записи можно удалить. История не содержит введённого текста. **Требуется добавить отдельную задачу в roadmap или убрать требование из релизного объёма.** | Не реализовано по имеющемуся описанию. |
| FR-11 | 3 | Пользователь явно запускает и останавливает запись согласованных типов действий, после чего может воспроизвести результат как шаблон. Во время записи и воспроизведения доступна остановка. Данные секретных полей не записываются. | Не реализовано по имеющемуся описанию. |
| FR-12 | 2 / MVP | Пользователь выбирает разрешённые клавиатурные действия, задаёт их интервалы и может включить/выключить их отдельно от перемещения мыши. Неверные параметры отклоняются; есть возможность остановить генерацию. | Не реализовано по имеющемуся описанию. |
| FR-13 | 3 | Пользователь просматривает список шаблонов, выбирает шаблон и проверяет его перед запуском. Неверный формат и недопустимые действия приводят к сообщению, исполнение не начинается. Базовый сценарий FR-07 не требует пользовательского шаблона. | Не реализовано по имеющемуся описанию. |
| FR-14 | 3–4 | Пользователь может вручную приостановить и возобновить сценарий; пауза не генерирует действий. Ошибка исполнения переводит приложение в безопасное состояние и отображается в UI. На этапе 4 добавляется автоматическое управление по FR-08. | Не реализовано по имеющемуся описанию. |
| FR-15 | 5 | Пользователь может включить браузерную интеграцию, выбрать поддерживаемый браузер и выполнить согласованный набор разрешённых действий. Если интеграция недоступна или нет разрешений, отображается понятная ошибка. Неподдерживаемые сценарии не исполняются. | Не реализовано по имеющемуся описанию. |
| FR-16 | 3 (шаблоны), 5 (перенос) | Пользователь импортирует и экспортирует шаблоны и настройки в документированном формате с номером версии. Некорректный файл отвергается без изменения действующей конфигурации. На этапе 5 проверяется перенос между устройствами. | Не реализовано по имеющемуся описанию. |

\* Колонка «Состояние прототипа» перенесена из прежнего описания и должна быть сверена с фактическим состоянием репозитория.

## Трассировка на roadmap

- **Этап 2:** FR-01–FR-07, FR-12 — окно, генерация ввода, параметры, горячие клавиши, локальное сохранение.
- **Этап 3:** FR-09, FR-11, FR-13, FR-14, FR-16 (импорт/экспорт шаблонов).
- **Этап 4:** FR-08, расширение FR-03 и FR-14 — ввод пользователя, пауза и экстренная остановка.
- **Этап 5:** FR-15 и перенос настроек по FR-16; проверка платформ относится к NFR-07.
- **Вне текущей roadmap:** FR-10 — локальная история; согласовать приоритет отдельно.
