# Busy Monkey — нефункциональные требования

**Версия:** 1.1 · **Дата:** 10.10.2026 · **Статус:** проект для согласования командой.

НФТ описывают **измеримые характеристики качества, безопасности и совместимости**. Числа ниже — целевые критерии, а не результаты проведённых испытаний. Требования, помеченные «после MVP», проверяются при реализации соответствующих этапов roadmap.

## Нефункциональные требования

| ID | Категория | Критерий приёмки и способ проверки |
| --- | --- | --- |
| NFR-01 | Отзывчивость (2, 4) | В 100 замерах p95 времени между командой остановки и прекращением генерации событий не превышает 500 мс. Для FR-08 отдельно измеряется время от физического ввода до приостановки. |
| NFR-02 | Надёжность (2–6) | 10 сеансов по 2 часа проходят без аварий и зависаний. Повторные команды запуска не создают двух одновременно исполняемых сценариев; завершение процесса приложения завершает и генерацию ввода. |
| NFR-03 | Производительность (2, 6) | Средняя общая загрузка CPU приложения и его дочерних процессов <= 2% полной мощности стенда за 10 минут базового сценария. Рост их суммарных private bytes между 5-й минутой и концом двухчасового сеанса <= 10 МБ. |
| NFR-04 | Удобство (2, 6) | Не менее 9 из 10 новых пользователей без подсказки выполняют настройку, запуск и остановку базового сценария. Для каждого из этих 9 пользователей первый запуск занимает <= 60 секунд после установки. |
| NFR-05 | Приватность (3, 5, 6) | Приложение не отправляет содержимое ввода, координаты курсора, шаблоны и историю сеансов без явного согласия пользователя. В MVP данные хранятся локально. Проверяются сетевой трафик, файлы конфигурации и логи. Запись FR-11 исключает секретные поля и требует явного включения. |
| NFR-06 | Безопасность (2–6) | Отказ в системном разрешении, ошибка API ввода и конфликт горячей клавиши не приводят к аварии; пользователь видит понятное сообщение. В логах нет паролей, токенов и секретов. **Если сервер входит в поставку:** нет фиксированных общих паролей, пароли хешируются средствами проверенной библиотеки, внешние подключения выполняются по HTTPS. |
| NFR-07 | Совместимость ОС (2, 5) | **MVP:** установка и базовая автоматизация на Windows 11 x64 под обычной учётной записью. **После MVP:** отдельные сборки и проверки на согласованных версиях Windows 10, Linux (раздельно X11 и Wayland, если поддерживаются) и macOS. Ограничения платформ документируются; недоступная функция завершается понятной ошибкой. |
| NFR-08 | Воспроизводимость сборки (1–6) | На чистом стенде сборка с зафиксированным `Cargo.lock` и флагом `--locked` проходит по документации. Зафиксированы версии Rust, Dioxus CLI, системные зависимости и команды запуска/тестирования. |
| NFR-09 | Совместимость браузера (5) | Перед реализацией FR-15 команда фиксирует список поддерживаемых браузеров и минимальных версий. На каждой заявленной комбинации выполняются тесты разрешённых сценариев; отсутствие API, нужных разрешений и неподдерживаемая версия обрабатываются без зависания приложения. |
| NFR-10 | Переносимость конфигураций (3, 5) | Экспорт содержит версию формата. Импорт корректного файла восстанавливает все документированные параметры и шаблоны; импорт повреждённого или несовместимого файла отвергается без потери текущих настроек. Проверяется на двух устройствах. |
| NFR-11 | Безопасное выполнение (3–6) | После подтверждённой остановки или аварийного выхода приложение больше не создаёт событий ввода; при паузе ввод не генерируется. Потеря системного разрешения, завершение приложения и ошибка шаблона не оставляют фоновый исполнитель активным. Проверка автоматизированными и ручными сценариями отказов. |

## Стенд и границы измерений

- **Базовый стенд MVP:** Windows 11 x64, >= 4 логических процессоров, >= 8 ГБ RAM, экран 1920×1080.
- Перед измерениями фиксируются конкретные CPU, ОС, объём RAM и сборка программы; результаты разных стендов не сравниваются напрямую.
- Базовый профиль: интервал 1000 мс, смещение курсора до 10 пикселей. После 5 минут прогрева измеряются CPU и память; CPU нормируется по полной мощности всех логических процессоров, дочерние процессы включаются.
- Численные значения предварительные. До согласования команда проверяет достижимость; изменение цели требует новой версии требований.
- Основной сценарий MVP должен работать локально без обязательного входа. Если в прототипе вход обязателен, это разрыв между текущей и целевой реализацией, а не свойство целевого MVP.
- Маскировка процесса и обещания необнаружимости в системах мониторинга не включены как гарантии. Статистика (если добавлена) описывает сеансы работы приложения, а не продуктивность сотрудника.
